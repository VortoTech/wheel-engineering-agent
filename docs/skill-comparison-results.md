# Wheel Skill 三组对照：Spark 开发集 pilot

日期：2026-09-28。协议见 [skill-comparison-protocol.md](skill-comparison-protocol.md)。

## 实验定义

- 两款既有开发/标定轮毂，每款测试完整规格与缺 ET，共 4 场景；每场景 A/B/C 各一次。
- A：Step3-VL-10B-FP8 + 通用受限 CSG 工具；B：Wheel Skill + 加工级 STEP；C：B + 造型 Agent。
- 图像、规格、模型调用、网格构建、STEP 构建及独立 STEP 回读均在 Spark 的隔离容器内运行。
- 容器 CPU 上限 6 核、内存 16 GiB；每次总预算 600 s，无几何修复重试。A 一次模型请求、4096 tokens；B 不调用 LLM；C 使用现有特征询问和渲染搜索。不是等 token / 等实际计算量对照。
- 镜像 `wheelcam-app:spark-20260928`，镜像 ID `sha256:668410682ed48c24e6c93b3f9876c9a8ea783f7426fd8d09b47def975f9afcaf`。
- v1/v2 为请求适配试运行，原因和中止记录见协议；两次原始记录保留在 `runs/skill-comparison-20260928/setup-records.tar.gz`。正式记录为 v3。

A 的失败为 **3 次输出截断、1 次输出不支持的 CSG 操作**。因此没有可比较的 A 几何精度，不能把其尺寸误差记为无穷大或宣称精度提升百分比。A 缺参项因流程未完成没有纳入共享理解评分，未评估不等于没有识别。

C 在 M59 的两种场景实际应用造型修改；在 case-01 两种场景保持原造型，四次均未回退为 Agent 失败。B/C 外形包络相同，不能宣称造型 Agent 提高外径或宽度精度。

结论：**当前 Skill 路线在这四个开发集场景中可稳定输出通过检查的加工级 STEP；通用基线尚未稳定产生有效工具计划，暂不足以给出强的 Skill 质量增益结论。** 下一轮应先在另行指定的基线开发输入上完善结构化工具调用，再冻结新版本；随后补统一视觉评分及独立 ET/PCD 计量。继续沿用这批数据时仍只称开发集复测。

## 解释边界

这批数据参与过模板标定；A 的通用工具表达能力受限，B/C 则拥有专业模板。它衡量此具体系统配置的结果，不能推广到所有无 Skill Agent，也不是纯提示词消融。

独立评分仅覆盖 STEP 单实体、回读体积及外径/总宽。中心孔只记录圆边候选；ET、PCD 孔轴、完整造型相似度没有统一独立评分。加工级 STEP 不包含完整造型曲面，所有产物均 `not_released`。

输出格式失败或截断必须单列：它说明该模型在当前输出协议下未给出可执行方案，不能直接证明其几何设计能力不如 Skill。若 A 无有效输出，下一步应先完善并冻结可运行的通用基线，再做质量对比，而不是宣传精度提升百分比。

- 对照页新增子版本和对话修改的参数前后表，显示校验/未采用状态。
