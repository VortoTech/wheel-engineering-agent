### 窗口棱边倒圆：整批改为逐窗口累进（2026-09-17）

原先一次性对全部棱边倒圆，只要任意两条相互干扰就整批失败，#18 / #20 / #21 因此一条都没倒上。改为按窗口逐个倒圆，每次在上一次的结果上继续，失败只损失该窗口。

| 照片 | 改前 | 改后 |
| --- | --- | --- |
| #29 | 29 / 38 | **31 / 38** |
| #21 | 0 / 48 | **8 / 48** |
| #26 | 4 / 22（36 s） | 4 / 22（31 s） |
| #25 | 15 / 20 | 15 / 20 |
| #20 | 0 / 44 | 0 / 44 |
| #18 | 0 / 34 | 0 / 34 |

半径都是完整的 2 mm；连接圆角与实体检查不受影响，没有一张退步。当时核心测试集 `pytest -q` 为 **104 passed**（384.40 秒）。发布收尾后，默认测试范围还包括 4 项标注/生成视图基准测试及发布元数据测试。

走过的弯路和结论：

- **按曲率给每条边单独限半径：失败，已回退。** 出发点是"轮廓拐角比圆角还急"（#20 最急 1.15 mm、#29 0.9 mm），但实测 #20 逐条试 2 mm 有 34/44 成功，说明曲率不是主要瓶颈。按曲率压半径反而把本能倒满的边削小：#29 掉到 11/38、#26 掉到 0/22。
- **加大轮廓平滑：无效。** #20 最急处加 8 mm 平滑也只能从 1.15 提到 2.02 mm，且会让窗口形状失真。
- **放宽子进程上限 100 → 150 s：无效，已回退。** #20 仍是 0/44，用时反而从 119 s 涨到 169 s。根本原因是**棱边倒圆后，合并本身会慢几倍**（#18 实测 133 s），窗口边多的轮毂必然超时。这是取舍，不是参数问题：连接圆角承受载荷，窗口棱边只是去锐边，超时后优先保住连接圆角。
- **踩坑与处理**：
  - 失败的 OCC 倒圆会原地改写输入实体的容差，输入随后与轮辋合并时得到两个无效实体。现在每次倒圆都在副本上进行。
  - 以前合并失败会直接交出无效实体，现在明确报错。
  - OCC 倒圆无法中途打断：#18 的一次合并尝试运行超过 20 分钟，#20 的一次窗口倒圆运行超过 12 分钟。窗口倒圆与合并改到子进程运行，按 100 s / 45 s 超时强制结束，最后退回在主进程里直接合并。工作台单次生成上限由 120 s 提高到 300 s。
  - 斜向或弯曲辐条会让任何径向线都穿过窗口，拟合改为按周期提取窗口。
  - 窗口轮廓按 3 mm 倒圆角，并避开中心盘夹持圆柱，否则棱边倒圆无法沿整圈进行。
