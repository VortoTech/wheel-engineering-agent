# v0.1 验证记录

日期：2026-09-12。

## 环境与依赖

macOS ARM64，Python 3.12.14，CadQuery 2.8.0，OCP 7.9.3.1.1，Node.js 25.2.0。Python 依赖由 `uv.lock` 固定，前端依赖由 `package-lock.json` 固定。

## 自动化验证

执行 `.venv/bin/python -m pytest -q --junitxml=artifacts/pytest.xml`，最终结果：**20 passed，5.98 秒**。

- 三组实体样例：默认六辐；五辐、380 mm 外径、负偏转；十辐、600 mm 外径、正偏转。
- 检查单一实体、拓扑有效性、外廓尺寸，使用内外点探针检查中心孔和安装孔。
- 无效参数、非整数轮辐数量、非有限数值和未知字段在进入 CAD 内核前拒绝。
- STEP 导出后回读，检查体积、尺寸与实体数量；GLB 检查文件结构和网格。
- 项目重启持久化、并发版本冲突、图片校验与原图摘要、参数与图片版本快照。
- 生成失败保留旧模型、中断任务恢复、第二个 worker 不抢占现有工作区，以及初始化和建模两个阶段的超时处理。

存在两条第三方测试客户端弃用提示（Starlette/httpx 与 anyio 的接口迁移），未造成测试失败。最初冷加载 CAD 原生库较慢；环境完成首次初始化后，最终测试耗时如上。工作进程已将原生库初始化与几何构建分别计时。

执行 `npm run build`，TypeScript 检查及 Vite 正式构建通过。构建产物中的主要 JavaScript 文件约 845 kB（gzip 约 231 kB），包含 Three.js；Vite 有文件体积提示。

## 实际接口生成样例

通过本地工作台代理接口创建“六辐概念样例”，提交真实 CAD 任务后成功，记录如下：

| 项目 | 结果 |
| --- | --- |
| 模板 | `radial-loft-concept-v1` |
| 模型版本 | `89f1061e18074c6790d1864e8817a80d` |
| 外廓 | 480 × 480 × 205 mm |
| 实体数 / 几何面数 | 1 / 41 |
| 体积 | 2,947,449.918 mm³ |
| 排队至完成 | 本次约 3.30 秒；不作为普遍性能承诺 |

| GLB | 209,936 bytes，下载返回 200 |
| 参数配方 / 检查报告 | 均下载成功，返回 200 |
| STEP 回读相对体积差 | 约 6.06 × 10⁻¹¹ |

样例文件位于 `data/models/89f1061e18074c6790d1864e8817a80d/`。本地数据、生成文件和运行日志不提交到源代码仓库。

使用与界面相同的 Three.js GLTFLoader 在 Node 中解析实际 GLB，读出 41 个网格；应用预览坐标转换后，深宽比与 205/480 一致。网格采样的 Y 向范围约 479.851 mm，和精确 CAD 外廓存在正常的离散化差异；加工几何以 STEP 实体为依据。

页面 `http://127.0.0.1:5178/` 和代理健康检查均返回 200，已打开本地工作台预览。API 使用 `127.0.0.1:18765`，避开原定端口上的既有服务。

## 验证边界

本次进行了 API 和几何测试、前端编译及预览打开；未进行浏览器点击流程、响应式截图或视觉验收。STEP 使用同一内核自动回读，尚未在独立 CAD 软件中人工验收。

尚未进行真实图片自动重建、毛坯匹配、独立 CAD 软件人工验收、CAM、机床程序验证、实物试切或轮毂性能验证。
