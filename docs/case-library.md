# 单图案例库与轮廓评估 · v0.9

2026-09-13。几何模板仍为 `forged-monoblock-v9`；本阶段新增案例复用和可追溯评估，没有改变历史模型或宣称复刻精度提高。

## 当前可用流程

1. 在右侧「案例」页收录当前展示的成功模型版本，填写名称、拟合经验和用途。模型必须在生成时绑定参考图；草稿修改不能改变已收录版本。
2. 可复用候选包含三项内置预设和本地收录案例。排序依据当前草稿的辐条类型、组数；不是照片语义分类或相似率。点击候选查看参数差异，再确认套用。
3. 按目标外径比例换算可见造型中的毫米参数。保留轮辋直径、宽度、ET、孔系、轴向厚度和加工准备；来源标为人工选择、非实测。超出模板约束时整次拒绝，不截断成另一个造型。
4. 套用后重新识图、应用候选并生成版本。在「照片对照与识图」展开「标注轮廓并量化偏差」，沿一段真实遮挡边界依次点击至少三点，保存评估。
5. 每次评估保存独立记录，可重看和下载 JSON；不反向参与几何或相机拟合。不同辐条、大小窗口和内侧分叉分别标注，便于定位差距。

## 案例数据与来源

SQLite 新增 `visual_cases`，一条成功模型版本只收录一次。记录图片 ID / 原始图片 SHA-256、模型 ID / GLB SHA-256、模板版本、固定参数及来源、说明、用途、几何限制。

案例状态固定为 `geometry_only`，`engineering_verified=false`。几何有效不表示原图吻合、真实尺寸正确或产品可加工。当前样例中的 22×8.5J、ET35、PCD114.3、CB66 等仍为假设。

项目新增 `case_selection`，每次生成快照带入案例 ID、来源模型和当时参数变更；修改之后仍可追溯最初套用来源。套用清除旧识图应用状态，需要重新识图。

用途为 `evaluation` 的案例及与它具有同一原图哈希的案例不参与推荐，也不能通过直接调用接口套用。它只提供保留集管理的起点：近重复照片、同款不同角度、由照片衍生的内置预设仍需人工分组，尚不能保证整个数据集没有泄漏。

## 轮廓指标的实际含义

算法 `projected-glb-boundary-v1` 读取当前展示版本真实 `wheel.glb`，处理 glTF 节点变换后恢复 CAD Z 轴，用该版本保存的相机投影全部实体三角形。三角形投影并集的内外遮挡边界作为距离基准；展示中心盖与周圈螺栓不参与。

标注折线按约 1 px 间隔采样，计算到最近实体投影边界的单向距离，输出平均值、P95、3 px 内占比及逐点误差。坐标和阈值对应识图分辨率，通常最长边 720 px；不是毫米公差。栅格化约有像素级误差，也不能识别表面棱线、高光或装饰槽。

评估与 `job_id`、图片 SHA、模型 SHA、相机分析 ID 和相机参数绑定。更换主图、版本不属于项目、点越界、草稿并发改变时拒绝保存。上方临时视图对齐滑块不参与评估。

这些指标只表示已标区域贴合程度。单向最近边距离可能匹配到相邻边，未标区域、缺失材料和额外材料没有被全面评价，因此不输出“整轮准确率”。人工标注也可能受到先前模型展示的影响，不能代替盲评。

## 接口

- `GET /api/cases`：模板与案例目录，包括仅供查看的保留集。
- `POST /api/projects/{id}/cases`：收录成功模型，输入 `job_id/name/note/role`。
- `GET /api/projects/{id}/case-candidates`：候选、排序原因、变更预览、基准 revision。
- `POST /api/projects/{id}/cases/{case_id}/apply`：带 `expected_revision` 原子套用。
- `POST /api/projects/{id}/builds/{job_id}/contour-reviews`：保存标注与评估，输入 `expected_revision/label/points`。
- `GET /api/projects/{id}/contour-reviews` 及 `/{review_id}`：历史及 JSON 下载。

## 下一步验收目标

1. 加入仅有照片的待标注案例，记录白底、透视、遮挡、轮毂结构和候选置信度；先判断是否属于现有单辐/双辐能力范围。
2. 新白底照片单独建样本，核对组数、孔数和大小窗口拓扑，不与旧工厂照片混作同款。白底利于边界提取，斜视仍需相机校正。
3. 标注连续闭合窗口、遮挡区域和关键转接点，以区域 IoU、双向距离、缺失/多余轮廓评价整轮，并按同款及原图来源划分拟合集和保留集。
4. 扩展模板族，再做结构检索与几何约束联合优化；保留多个候选及未知尺寸。当前库不是自动学习或已训练的视觉模型。

## 数据与交付

案例和标注保存在本地 `data/wheelcam.sqlite3`；原图、STEP、GLB 仍在 `data/`。Git 跟踪代码和文档，不包含本地案例数据，备份时必须同时保存数据库、images 和 models。结构化案例库供程序使用；共享知识库文章记录路线、决策和验证，两者职责不同。
