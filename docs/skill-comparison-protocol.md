# Wheel Skill 三组系统对照 · 预注册 v1

## 冻结范围

M59 case-03/d20w10.5 与 case-01/d20w10，均为开发/标定样本；每款有完整规格和移除 ET 两种场景，共 4 场景 × 3 组 = 12 次尝试。仅用脱敏正面效果图、提供的规格与孔型，三组不提供斜视图。参考 CAD 的 truth.json 只给独立评分器。不得据此声称新款泛化。

- A：同一 Spark VLM，通用 CSG JSON 基础工具（圆柱、盒体、旋转体、多边形挤出、并/差、旋转阵列）。不调用轮毂模块，不执行模型生成的代码。
- B：Wheel Skill 图像重建 + 加工级 STEP。
- C：B 的流程开启造型 Agent，再生成加工级 STEP。

相同 Spark 主机、6 CPU / 16 GiB 容器限额、OCCT/CadQuery 内核，每次最多 600 s，一个尝试，无失败后人工修复。A 最大输出 4096 tokens，一次模型请求；B 的默认视觉几何流程不调用语言模型；C 使用已有造型 Agent 的特征询问与搜索。记录真实调用差异，不宣称三组消耗完全等量计算。不同场景轮换组别顺序。代码和输入哈希在模型调用前写 manifest，所有失败留在分母。

## 评分与边界

共享独立评分器从导出的 STEP 重新导入，检查有效单实体、二次导出回读体积差，测量外径和轴向总宽，与既有工厂 CAD 真值比较。提供中心孔圆边候选及原始圆边证据；这不是完整孔系轴线计量。来源保留与缺失 ET 声明另外计分，不把报告字段正确等同实际几何正确。

本轮是**受限通用工具基线的系统对照 pilot**，不是纯提示词 Skill 消融，也不是对所有通用 Agent 的结论。A 的几何表达与 B/C 不同；B/C STEP 是简化加工级实体，不包含完整造型曲面。完整视觉质量、独立 ET/PCD 计量、人工修正工时暂不具备统一评分器，明确 `unavailable`，不纳入胜负统计。两组 Skill 共享已标定的模板，必须披露。

当前首先验证通用基线能否执行、三组产物能否被统一评估以及缺参语义；结果不能单独证明完整 Wheel Skill 的商业收益。后续再扩充生成工具表达、统一可见表面视觉评价和新款输入。所有产物 `not_released`。

## 复现

```sh
PYTHONPATH=services python scripts/skill_comparison/run.py \
  /orders/case-03/d20w10.5 /orders/case-01/d20w10 \
  --out /output/pilot --budget 600
```

设置 `WHEELCAM_VLM_BASE_URL` 和 `WHEELCAM_VLM_MODEL` 指向已获授权的本地模型；输出目录必须为空。

## 执行记录

2026-09-28 的 v1 在首个 A 请求出现 180 s 客户端超时后终止（其 B 已完成，C 被中止）；原目录保留，不计入正式三组摘要。模型服务实测约 19 tokens/s，4096 tokens 可能超过这一客户端上限，原配置与 600 s 总预算不一致。

v2 仅将 A 的 HTTP 请求上限对齐总预算，并将预算显式传给工作进程。使用新的源代码副本、输出目录和 manifest，从头运行所有 12 次；未调整提示词、模型、输出 token 上限、输入或几何规则。v1 的超时不作为 Skill 效果证据。若模型触及输出 token 上限，分类为输出截断，不解释为几何能力不足；完成流程与有效实体分别计数。

前端本轮另增加两处评审辅助：参考图任务在盲窗数量为零时提示核对；“对照”页汇总子版本和对话的造型参数前后值。它们是工作台可解释性改进，不属于本次几何评分。

v2 在得到首个完整响应后确认 A 以 `finish_reason=length` 用满 4096 tokens，解析不到 `geometry`。检查现有 `text_wheel.py` / `recipe_chat.py` 后发现它们已使用 `response_format=json_object`，本基线遗漏。v2 因适配不完整中止并保留，不能用于声称 Skill 优势。

v3 补齐同样的 JSON 输出模式，再从头运行 12 次。三版输入、几何工具、提示词、模型和模板均未调参；只有请求适配修正。**因此这是有两次适配试运行记录的开发集 pilot，不是未经试运行的盲测。** v3 内所有失败仍计入 12 次尝试，不删失败、不替换案例。
