# 首版范围与实施路线

日期：2026-09-12。状态：已进入 P0 几何验证与 P1 人工参数工作台实现，具体进度见 [本地工作台](local-workbench.md) 和 [验证记录](validation.md)。

## 1. 首版目标

在暂时没有工厂软件和设备配置的条件下，首先证明：一组参考图片加明确参数，能够稳定生成一类可编辑的轮毂实体；导入毛坯后，能够识别缺料和加工余量问题；结果可交给 CAD/CAM 工程师继续处理。

首版范围为一类简单的周期性轮辐模板、手动确认参数、STEP / GLB 导出和基础毛坯匹配。实际 CNC 输出作为后续工厂接入里程碑，保留在总体目标内。

## 2. 分阶段交付与验收

| 阶段 | 交付 | 验收依据 |
| --- | --- | --- |
| P0 几何可行性 | 一类轮毂模板、参数范围、基准样例、已知失败案例 | 参数变化能重建实体；体积、连通性及关键尺寸检查符合样例约定；STEP 在独立 CAD 查看器中核对 |
| P1 交互建模 MVP | 多图管理、候选特征、参数编辑、3D 对照、版本保存和导出 | 从图片进入模板并经人工确认；修改参数可重建；保留参数来源；失败不会覆盖上一版 |
| P2 毛坯与工艺准备 | 毛坯导入、基准对齐、缺料与余量检查、加工特征、工艺交接包 | 至少覆盖可匹配、局部缺料、错单位或错坐标的明确样例；无实际毛坯时标记为概念结果 |
| P3 单工序 CAM 验证 | 一台实际机床、一道工序、一套装夹的 CAM 接入与 NC 输出 | CAM 和后处理版本固定；记录仿真范围；工程师核对程序；现场受控试切和首件检查留存 |
| P4 完整加工流程 | 多装夹、工序间毛坯继承、车削与钻铣衔接、交付包 | 各程序与坐标和工序版本一致，完整首件工艺验证通过 |

P0 可以用有明确尺寸的合成工程样例验证软件几何，不将其称为合格轮毂设计。涉及真实轮毂设计和加工的验收应由相应工程师参与。

## 3. 第一个可演示流程

1. 新建轮毂项目，上传正面、斜视和可用的背面或侧面参考图，选择主参考。
2. 系统提出轮辐数量与造型候选，展示图片中的依据与不确定项。
3. 用户确认模板，输入已知尺寸；未知字段单独列出。
4. 调整轮辐宽度、凹深等模板支持的参数，在浏览器中旋转和查看剖面。
5. 保存参数版本，导出 STEP 与 GLB；标注工程审核状态。
6. 导入毛坯并对齐，查看缺料和余量报告。
7. 生成用于 CAM 交接的成品、毛坯、坐标和加工特征包。

第一版的价值是缩短图片到可修改工程模型及加工准备的过程。自动加工图、完整工艺自动规划、通用后处理和量产发布不作为 P1 的完成条件。

## 4. 开发顺序

建议先实现几何验证，再做页面与 AI 接入：

1. 定义 WheelSpec、参数来源、单位、坐标和模板参数范围。
2. 建立一类轮毂模板与几何验证样例，评估圆角和复杂轮辐限制。
3. 实现参数 → 实体 → STEP / GLB 的任务流程和版本保存。
4. 实现参数编辑与三维对照工作台。
5. 引入图片特征提取，只自动填充待确认候选。
6. 加入毛坯对齐与差异分析，生成工艺交接包。
7. 在确定合作工厂后验证 CAM、后处理和单工序加工。

## 5. 评价指标

| 维度 | 衡量方式 |
| --- | --- |
| 设计效率 | 从录入图片与规格到首个可编辑 CAD 的时间及人工修改次数 |
| 几何稳定性 | 已定义参数范围内的构建成功率、错误定位及恢复能力 |
| 造型一致性 | 对照选定视角和可用工程资料，由设计者确认；与尺寸精度分开评价 |
| 工程正确性 | 在已指定公差和基准下核对关键尺寸；不能用视觉相似度代替 |
| 毛坯检查 | 明确缺料和足够余量样例的检测结果及边界情况 |
| 工艺效果 | 接入工厂后比较编程耗时、试切记录、尺寸结果和实际节拍 |

先建立样例和基线，再设置成功率、耗时与误差目标；当前不承诺任意图片的自动化率或加工精度。

这些资料不阻塞当前框架设计及数字样机开发，分别限制后续的工程设计、毛坯结论或 NC 交付。

## 7. 协作角色

软件和 AI 开发负责工作台、任务、参数与集成；轮毂设计工程师负责功能几何、材料、载荷及设计审核；工艺工程师负责毛坯、装夹、刀具、CAM 和后处理；工厂负责现场验证和首件检查。早期可以由一位具备相应经验的工程师参与多个环节。

在 P0 明确几何难度、P3 确定工厂条件后再估算工期与成本。软件原型完成、机床加工验证完成、轮毂产品验证完成是三个不同的里程碑。
