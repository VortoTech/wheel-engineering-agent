# 私有工程资产评测：Wheel Skill 的下一道验收

2026-09-27。数据源由用户提供于本机 `~/personal_project/asset`。此文档只记录文件类型、评测方法和本机试跑结果；客户原始图纸、表格、CAD、效果图及其绝对路径不进入版本库或公开提交物。对外演示范围需按素材授权单独决定。

## 当前盘点与证据等级

运行 `python3 scripts/asset_eval_intake.py --asset-root ~/personal_project/asset --out artifacts/asset-eval/intake.json`，生成忽略版本控制的只读盘点。当前得到 7 个型号文件夹、55 个文件：21 张设计效果图、13 个 Parasolid `.x_t`、9 个 DWG、7 个 `.xls`、5 个 `.xlsx`。13 个 `.x_t` 按 SHA-256 去重后为 11 个文件版本；HN191 与 HN192 的两组尺寸分别字节相同，必须放在同一评测分组。

这些图是工程项目的**渲染效果图**，不是实物拍摄照片。文件名里的尺寸是 `filename_unverified` 候选；只有对照确认单、DWG 及对应的三维模型后，才能把它提升为 `drawing` 或 `measurement` 来源。M62/M63 目前只有 `.xls`，还没有读入或核对其单元格；不能仅凭效果图上的文字认证规格。

仓库已有 `experiments/real-orders/ingest.py`，目标是抽取订单工程字段、把双轮效果图分成单轮输入并清理私人字段；它是下一步的正式输入准备入口。2026-09-27 对每个系列的首张正面效果图做了**只读**的 `wheels()` 数量检查：HN191/HN192/M59/M60/M62/M63 各得到 2 个轮毂，M61 得到 1 个。这个检查尚未证明视角顺序、前后轮尺寸配对、全部视图的清理及 `.xls` 解析正确。新增的 `asset_eval_intake.py` 只负责文件清单、哈希与重复真值检查，不替代现有导入器。

## 当前软件链路在 M61 上的试跑

M61 是开发样本，不能再作为冻结测试样本。使用其单轮正面原图及确认单中 `22×10, 6×139.7, CB93.4, ET-5`，本机同一轮的观察为：

| 阶段 | 结果 | 边界 |
| --- | --- | --- |
| 旧正面识别 | 1.51 秒后误判“不是正视图” | 文字和地面阴影污染整图包络 |
| 修正正面识别和周期规则后 | 2.77 秒生成 L0 理解报告；6 组、每组 2 个窗口 | 调整了规则，因此 M61 是调试样本 |
| 网格与正面对照 | 42.45 秒；GLB 输出；窗口 IoU 0.967，边缘误差指标 3.5 mm | 同一张输入图的外观拟合；是 L0，未生成 STEP，也未与 `.x_t` 比较 |

上述是探索性前后记录，不是固定代码基线、冻结样本和同条件批量评测。模型没有用斜视图，也没有在 DGX Spark 运行；`--use-vlm` 未开启。本轮几何内核的网格检查无失败，不证明 B-Rep 构造会成功。

## 建立可复核的评测集

1. **逐版本配对。** 扩展并验证现有 `experiments/real-orders/ingest.py` 的每个型号/尺寸 case ID，链接原始图哈希、正面/斜视视图位置、六项规格及单元格/图纸出处、相应 `.x_t` 和 DWG 哈希。双轮合成效果图需要隔离单个轮毂并排除写在图上的参数文字；保留原图哈希和处理方法。不能把并排的前后轮误当同一个轮毂的两个视角。
2. **CAD 真值。** 用经验证的 Parasolid 读取或转换工具生成可回读的参考 STEP，并记录软件版本、单位、实体数、体积、包络和哈希。转换未通过则该 case 的三维对照标记 `UNAVAILABLE`，不以图像指标填补。
3. **冻结划分。** M61 已用于修正规则，是 development。HN191/HN192 必须在同一分组。初次验收拟冻结 HN、M59、M60、M62、M63 五个造型系列；在配对、转换工具和评分代码锁定前不运行这些型号的 Skill 分数。看过结果后不得针对冻结集调参再把它称为独立验收；若调参则建立新的冻结集。
4. **冻结输入契约。** Agent 只接收规定的单轮图和已确认的少量规格；完整 DWG、参考 `.x_t`、评价结果留在验收侧。把输入规格来源和未提供项写入 `engineering_report.json`，不可从图片文字抄录为用户实测。

## 分开计分

| 维度 | 记录的结果 | 不成立的替代解释 |
| --- | --- | --- |
| 理解与决策 | 结构/周期候选是否正确；来源和未知项是否正确；Agent 何时询问、选择内核、停止或重试 | 一份静态计划不等于真实 Agent 决策 |
| 外观 | 正面/斜视窗口 IoU、边缘距离、逐款叠加图 | 不等于三维尺寸或制造精度 |
| CAD 构造 | 每次构建成功/失败、单有效 Solid、STEP 回读、体积差、耗时 | 网格 GLB 成功不算 STEP 成功 |
| 工程尺寸 | 六项有来源的规格与独立 CAD/图纸测量逐项对比，另列无法独立测量的 ET | 配方值吻合不等于独立 STEP 计量 |
| 参考 CAD | 统一单位和坐标后的包络、体积、截面、表面距离；注明不可观察的背部差异 | 不能声称从正面图恢复了背面真实结构 |
| DGX Spark | 节点、模型、服务端点、调用、GPU/内存、时延、工具调用与结果哈希 | 把本机 CAD 或离线录屏说成全链本地运行 |

评测报告必须列出 **成功数/尝试数** 和每个失败原因。前后优化只比较相同原始输入、相同规格、相同内核、相同硬件、相同评分代码，并分别公布质量和时间。若没有人工建模时间基线，不声称节省工程师工时。所有输出仍为 `manufacturing_status=not_released`。

## 项目优化顺序

1. 完成私有 case manifest、单轮输入和规格核对；把 M61 当开发样本，冻结其它独立造型。
2. 验证 `.x_t`→参考 STEP 或等效读取路径，并实现只读的几何比较。缺少这一层不能宣称“接近真实 CAD”。
3. 在本机逐款跑理解和网格基线，修正重复周期、图像预处理与窗口表达；报告失败，不靠人工选择最好轮廓覆盖自动结果。
4. 在有界的代表性样本上解决 B-Rep 布尔失败，再跑冻结集的 STEP 回读和尺寸检查。只有这一步成功，才讨论 L1/L2。
5. 在获准处理该素材的 DGX Spark 环境中运行本地视觉模型，保存实际请求/响应和 Agent 决策；用同一评测集证明 Skill 的作用。现场演示可回放耗时构建，但必须标注预先完成并绑定同一输入哈希。

当前结论：**已证明 M61 的工程理解与 L0 正面预览可运行；尚未证明参考 CAD 精度、跨造型成功率、STEP 稳定性或 Spark 端到端。**

参考 STEP 的首选来源是原设计方直接导出；若无法取得，先用本机软件验证 `.x_t` 转换，不能用未验证的网格代替精确 CAD。厂商资料显示 [CAD Exchanger Lab](https://cadexchanger.com/products/gui/) 可在 macOS 本地查看并导出 STEP；[Autodesk Fusion 支持格式表](https://help.autodesk.com/view/fusion360/ENU/?guid=TPD-SUPPORTED-FILE-FORMATS)列出 Parasolid 输入，但个人版可用性和具体版本必须按实际许可检查。这些路径目前均未在本机完成导入/导出验证。
