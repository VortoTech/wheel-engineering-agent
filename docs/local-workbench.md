# 本地工作台 v0.1

日期：2026-09-12。

## 当前实现范围

此版本对应 P0 的参数化几何验证与 P1 的人工参数工作台。图片作为人工参考保存；自动识图、毛坯匹配、CAM 和 NC 输出尚未实现。

| 功能 | 实现方式 |
| --- | --- |
| 项目和参数 | SQLite 保存项目、参数来源和草稿版本，使用版本号检测并发覆盖 |
| 参考图片 | 最多 20 张，保存原文件及 SHA-256，同时生成去除 EXIF 的预览 JPEG |
| 参数化建模 | 固定版本的 CadQuery 模板，轮辋旋转体 + 中心盘 + 放样轮辐阵列 + 孔系 |
| 三维预览 | 显示实体导出的 GLB，支持旋转、缩放、正面视图、线框与单侧剖切 |
| 模型生成 | API 排队，独立 Python 子进程执行 CAD；首次内核初始化最多 600 秒，初始化后实体生成最多 120 秒 |
| 导出与版本 | 每次生成保存独立 STEP、GLB、参数配方和检查报告，历史文件不覆盖 |
| 失败与恢复 | 无效参数在生成前拒绝；失败保留上一版；中断任务重启后标记失败，可重新生成 |

剖切视图通过裁剪显示一半模型，不生成带填充的工程剖面，也不修改导出的实体。

## 模板定义

模板编号：`forged-monoblock-v2`（锻造单片轮毂，2026-09-12 起替代 `radial-loft-concept-v1`）。纯数学布局在 `services/wheelcam/template.py`，CAD 构建在 `geometry.py`。

采用毫米，右手系，轮毂轴线为 Z，轮辋宽度中面为 Z=0，+Z 为外侧（装饰面）。

| 部分 | 构造 |
| --- | --- |
| 轮辋截面 | 按“直径 × 宽度 J”换算胎圈座直径与轮缘内侧间距；近似 J 型轮缘（高 17.5 mm）、5° 胎圈座、安全凸峰、外侧深槽；轮缘厚度 = 壁厚 + 5 mm，胎圈座与轮辐外端区域壁厚 = 壁厚 + 1.5 mm；截面各角带圆角后整体旋转 |
| 中心盘 | 从安装面 Z = ET 起，厚度可调；前缘圆角；中心孔贯通 |
| 安装孔 | 贯通孔 + 60° 锥面座 + 套筒避让沉孔；锥面座底距安装面 14 mm |
| 轮辐 | 5 个竖直截面放样：根部 / 外端宽度线性过渡，厚度外端为根部的 70%；两侧 6° 拔模，正面拱高与棱边圆角可调；偏转按平滑曲线分布，两端截面沿径向；“凹面曲率”控制正面从中心盘到轮缘的下沉形状 |
| 背腔 | 轮辐背面在 22%–78% 段铣出减重腔，侧壁 ≥ 5 mm，正面蒙皮 ≥ 6 mm，腔底圆角 3 mm（刀具半径） |
| 连接圆角 | 轮辐与中心盘、轮辋相交线统一倒圆；失败时降到一半，再不行则不倒圆，实际值写入检查报告与限制说明 |

派生尺寸（实际外径、整体宽度、背距、凹面深度等）由模板计算，写入 `report.json` 的 `derived`，并在检查页展示。外廓检查按派生的外径与整体宽度核对。

参数组合在进入 CAD 内核前做可行性校验：ET 与中心盘厚度是否超出轮缘外端面、中心盘能否包住轮辐根部、安装孔沉孔与中心盘外缘及中心孔的间隔、轮辐根部是否相互重叠、深槽能否放下、背腔是否放得下。不可行的组合直接返回中文原因，不排队。

轮辋截面只是近似标准轮廓，未逐项核对 ETRTO / TRA 图表；尚未加入气门孔、平衡配重面与中心盖安装结构，模型不能作为轮胎配合或加工依据。

旧模板保存的草稿在服务启动时迁移：仍存在且有效的字段保留数值与来源，其余采用新模板默认值并标注“模板升级”。历史生成版本的参数快照不改动，旧模板参数不能载入当前模板。

所有初始值标记为“模板假设”；修改后默认标记为“手动输入”。可将来源改为图纸标注或实物测量，但来源标签本身不表示工程审核通过。

## 数据位置

```text
data/
  wheelcam.sqlite3
  images/
    <image-id>.source      原始图片
    <image-id>.jpg         标准化预览
  models/
    <job-id>/
      recipe.json         精确的参数、来源、模板与参考图快照
      wheel.step          工程几何交换文件
      wheel.glb           浏览器预览
      report.json         几何检查与文件摘要
      build.log           CAD 运行日志
    <job-id>.building/    运行中或失败的中间记录
```

通过 `WHEELCAM_DATA_DIR` 可指定数据目录。备份时停止本地服务，整体复制数据目录；源代码与数据目录分开管理。

## 运行方式

开发模式使用根目录 `npm run dev`，同时运行 API 与前端开发服务。工作台地址为 `http://127.0.0.1:5178`，API 为 `http://127.0.0.1:18765`。

生产资源构建完成后，也可只启动 API，通过 `http://127.0.0.1:18765` 使用完整本地工作台。服务仅供本机使用；当前工作进程采用单实例设计，不应启用多个 Uvicorn worker 共用同一个数据目录。

## 验证方法及边界

- 几何样例覆盖默认 18×8.5J、20 英寸五辐深凹、17 英寸十辐、22 英寸七辐极限参数；检查实体有效、连通、外廓尺寸和连接圆角实际值。
- 用实体内外点探针检查中心孔、安装孔、沉孔、轮辋截面各区和轮辐背腔确实存在，而不是只读取输入参数。
- 测试通过 `tests/conftest.py` 使用临时数据目录，不触碰本机 `data/`。
- STEP 导出后经同一 CAD 内核重新读入，比较实体数量、外廓与体积；这是自动回读验证，尚不等于独立商业 CAD 软件的人工验收。
- GLB 检查文件头与网格数据，前端执行类型检查和正式构建。
- API 测试覆盖草稿并发冲突、重启持久化、图片格式校验、版本快照、生成失败保留旧模型和中断恢复。

具体执行结果记录在 [验证记录](validation.md)。上述参数样例只证明所测样例，不证明整个参数组合空间均可成功生成；实际失败会返回明确状态。

## 后续开发入口

1. 选定一款真实轮毂，补充图片和尺寸，评估模板拟合能力。
2. 接入图片候选特征提取，保留人工确认；使用真实样例评价造型一致性。
3. 增加 STEP 毛坯导入、坐标对齐和缺料检查。
4. 确定工厂设备和 CAM 后再实现对应适配器。
