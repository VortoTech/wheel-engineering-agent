# PRD · 黑客松最终演示：从商品图到 CNC 加工包

2026-09-27 起草，比赛 2026-09-29 结束。本文件只约束参赛演示的范围、验收和排期；产品定义与准备等级沿用
[V0.1 产品定义](product-v0.1.md)，不在这里重复。

## 1. 目标

用一个真实订单证明整条链能跑通：**订单渲染图 + 确认单规格 → 三维模型 → 工程图 → CNC 加工包 → 加工仿真**。
同时用 13 个真实工厂模型给出两个可复核的数字：跨款式建模成功率，以及和原始 CAD 的误差。
所有生成物都是**待工程师审核的初稿**，不是制造发布文件。

## 2. 用户与场景

锻造轮毂工厂的设计/工艺人员。拿到客户的造型图和确认单后，要在 NX 里重建模型、出图、编 CAM。
演示要证明：初稿可以自动生成，而且每个尺寸都能说清来源、误差和是否已校验。

## 3. 输入

| 输入 | 来源 | 说明 |
|---|---|---|
| 正面、斜视渲染图 | 真实订单（脱敏后） | 一个轮子一张图，去掉角标文字和元数据 |
| 六项规格 + 孔型 | 确认单 | 尺寸、ET、中心孔、PCD、孔数；孔型 15×32×60（孔径 15、锥座 32、60°） |
| 毛坯型号 | 确认单 | 用于 CNC 选料 |
| 工厂 CAD（x_t） | 真实订单 | **只作对照真值，不作输入** |

## 4. 功能与验收

| # | 功能 | 输出 | 验收标准 |
|---|---|---|---|
| F1 | 重建 | GLB 预览、配方；能建成时出 STEP | 辐条数、窗口组数和渲染图一致；孔系、ET、单一实体检查通过 |
| F2 | 锥形螺栓座 | 按孔型建孔：孔径 15、锥座 32、60° | 和工厂 CAD 的孔径、锥角一致 |
| F3 | 和原始 CAD 对照 | compare.json + 截面叠加图 | 7 项关键尺寸误差；截面边中位误差、P90 误差 |
| F4 | 跨款式成功率 | summary.json | 13 个模型：网格建成率、STEP 建成且回读通过的比例，失败项写明原因 |
| F5 | 工程图 | PDF/SVG：正视图 + 半剖视图 | 标注外径、宽度、ET、PCD×孔数、中心孔、孔型；标题栏；"未发布"章 |
| F6 | CNC 加工包 | G 代码 + 刀具表 + 工序单 | 车削回转轮廓；钻孔（G81）；窗口 2.5 维分层粗加工（6 mm 刀）；曲面精加工注明"交工厂 CAM" |
| F7 | 加工仿真 | 锻坯切削后的渲染图 | 刀具扫掠体从毛坯中去除；和设计模型对比残料 |
| F8 | 对话式修改 | 网页工作台里的对话框 | 自然语言 → 白名单造型参数（带范围）→ 重建 → 重新校验；PCD/ET/中心孔等工程约束拒绝修改并说明 |
| F9 | Spark 部署 | 容器化应用 + 本地模型 | 在 DGX Spark 上一条命令跑完 F1–F7；对话用 Spark 本地模型；只经 SSH 隧道访问 |

## 5. 指标（演示时如实展示）

- 跨款式成功率：网格 x/13，STEP x/13。
- 和 CAD 的误差：每个模型 7 项尺寸误差，截面中位误差和 P90 误差。
- 用时：单模型网格重建、STEP 构建、整条链总时长（Spark）。
- 截至 2026-09-28（Spark 实测，13 个模型）：
  - 网格 13/13；加工级 STEP（车削回转体 + 直壁通窗 + 锥座孔系）13/13 通过单实体、STEP 回读、无碎面，
    每个 16–46 s；完整造型 STEP 13/13 写出，5/13 通过回读（L2 及以上），1/13（M59）无跳过工序、全部校验通过。
  - 外径误差 0（轮缘高度 19.9 mm），ET ±0.05 mm，PCD/孔数/中心孔准确；孔型读到的 9 个模型孔径误差 0，
    其余 4 个确认单未给孔型，仍是 22 mm 模板孔（+7 mm）。总宽 −4.9…+1.4 mm。
  - 轮辋截面中位误差 0.94–3.03 mm（中位 1.98 mm）；M59 从 3.84 降到 1.98 mm。
  - 标准轮辋截面、轮缘高度和宽度附加量都由这同一批 13 个 CAD 标定，以上是同批残差，不是泛化精度。

## 6. 隐私

原始订单不进仓库、不上 Spark；只用 `experiments/real-orders/ingest.py` 的脱敏输出。
客户与员工姓名、机器名、路径只存在本机 `~/.wheelcam/` 的敏感词清单里，`tests/test_privacy.py` 扫描整个仓库。
路演如需隐藏标志，用 `--blur-logos` 重新导入。

## 7. 部署（F9）

```
Mac ──SSH 隧道──▶ DGX Spark（只绑定 127.0.0.1）
                 ├─ wheelcam-app：Python 3.12 + cadquery-ocp 8.0.1 + manifold3d（均有 ARM64 包）
                 │                批量评测、全链路、网页工作台
                 └─ wc-qwen：eugr/spark-vllm 镜像 + Qwen（端口 8011，关闭思考，输出 JSON）
```

遵守节点手册：不动 `lp-vllm`，不改系统配置，长任务放 tmux，不传大于 1 GB 的文件，不开放公网端口，
不上传未授权数据（Vossen 评测照片不上传）。B-rep 建模是单线程 CPU 运算，Spark 的收益在于 20 核并行。

## 10. 风险

| 风险 | 应对 |
|---|---|
| STEP（B-rep）跨款式成功率低 | 已应对：加工级 STEP（13/13）作为加工与图纸的依据；完整造型 STEP 按步骤降级，失败的造型工序跳过并写进报告 |
| M59 外观不够像 | 最多调 2 小时；不行就改用 case-07（M63）当主角 |
| Spark 环境装不上 | 本机保留一套能跑的全链路；Spark 只跑模型和批量评测 |
| 对话模型输出不稳定 | 只允许白名单参数和 JSON 结构；解析失败就追问，不猜 |
