# Wheel Skill 统一工作台流程

2026-09-28。本页对应 `wheelcam.workbench` 参赛工作台，与旧 `wheelcam.app` 项目编辑器分开。

## 使用方式

```bash
PYTHONPATH=services .venv/bin/python -m wheelcam.workbench --runs runs/demo --port 8790
```

打开 `http://127.0.0.1:8790`。

1. **用图片新建**：上传正面图，可加斜视图；填写已知尺寸和孔型，空白保留未知。图片经过方向纠正和 JPEG 标准化，去除 EXIF，单张最多 10 MB / 3000 万像素。调用 Wheel Skill 本地几何识图生成预览。此入口不自动把图片发送给视觉模型。
2. **用文字新建**：沿用现有文字入口，先生成预览，再按需生成交付包；连接已配置的 `WHEELCAM_CHAT_*` / `WHEELCAM_AGENT_*` 模型。模型只提议受支持的造型，原文尺寸和默认值分别记录。
3. **对话修改**：逐轮修改受白名单约束的造型，重建、校验后更新 GLB。失败保留上一版。它不能直接改工程尺寸。
4. **确认工程尺寸**：填需要确认或修改的字段，查看旧值→新值，勾选来源确认。空白字段不修改，也不冒充已确认；例如仅确认 ET 不会把其余默认尺寸标为用户输入。直径改变时按比例缩放窗口轮廓并记录为规则派生，不能当成重新识图结果。
5. **生成当前版本交付包**：冻结当前通过校验的配方，生成新任务；依次重建网格、加工级 STEP、加工准备包和工程图。不重新调用模型决定造型。父版本保留，顶部列表可回看。

每轮需等待完成；没有中途打断、流式 CAD 或实时连续编辑。文字和造型对话仍要求模型服务可用。

## 版本和验证

- 新版本使用独立 `revision-*` / `delivery-*` 目录；`chain.json.parent` 记录父任务、父配方 SHA-256 和本次确认项。
- 接口使用 `expected_recipe_sha256` 拒绝过期页面请求。同一运行的修改、恢复和导出在单进程内串行；服务应按默认单 worker 启动。
- `--snapshot` 从冻结配方重建，不从旧加工配方或模型响应重建；`--preview-only` 用于尺寸确认与图片新建。
- `delivery_manifest.json` 记录源配方 SHA-256、产物哈希、父版本及是否完整；仅预览不会标为完整交付包。
- 新配方重新生成校验、质量和文件哈希，不沿用旧配方的视觉分数与产物证据。
- 重建失败的新版本不会进入可选列表；STEP 校验失败则不继续生成加工包。加工包单独失败时保留失败记录，界面明确显示未完成。
- 工程图接收加工报告中的调整及未进入 STEP 的造型限制。

**加工级 STEP 是同一版本配方派生的制造准备几何，不等于完整造型 GLB。** 造型面、结构仿真、制造审核仍有边界。所有产物保留 `not_released`，参考轨迹不能上机。
