# 产品全貌：核心架构、当前 PRD 与发展路线

更新：2026-09-29。产品：**VortoTech · Wheel Engineering Agent**。本页是当前产品范围与发展方向的统一阅读入口，以已实现代码和验收记录为依据；具体模块与历史试验见文末链接。

## 1. 产品定位与核心

**将轮毂图片、文字需求和已知工程尺寸，转化为可调整、可追溯、可检查的工程草案，供工程师审核和继续设计。**

长期方向是 Engineering Reconstruction Agent；当前只落地第一个垂直能力 **Wheel Engineering Skill**。用户是轮毂设计、CAD、逆向工程及工艺人员。最小使用场景是“收到造型参考和几个尺寸，快速得到可审阅初稿，并持续修改”。

核心是视觉或语言模型与 CAD 内核之间的 **工程约束与证据层（Engineering Constraint Intelligence）**：

- 哪些零件和参数有工程含义，彼此怎样关联；
- 哪些信息来自用户、图纸、观测、模板或规则，哪些仍未知；
- 模型能修改哪些造型，工程尺寸如何保持或经确认修改；
- 怎样把配方构造成几何，怎样处理失败和缺失工序；
- 怎样验证实际产物，并限制报告能作出的结论。

这些规则已分布在多个 Python 模块及 Skill 契约中，尚不是独立通用约束求解器。核心资产的积累方向是**领域规则、可复用构建流程、验证方法和真实修正记录**。

## 2. 当前架构：实际怎样运行

```text
工作台 workbench.py / workbench.html    或    Skill 调用脚本 / CLI
                         │
           ┌─────────────┴──────────────┐
           │                            │
   图片 + 已知规格                 文字需求 + 已知规格
    wheel_skill.py                  text_wheel.py
   观测、轮廓与配方             模型提案 → 确定性审核
           │                  私有造型库 / 参数预设
           └─────────────┬──────────────┘
                         │
              recipe.json + 参数来源 / 未知 / 调整
                         │
          ┌──────────────┼────────────────────┐
          │              │                    │
     mesh_build      forged_blank        machining_step
     快速造型网格     完整造型 B-Rep 候选    简化加工实体与毛坯
        GLB             STEP            machining.step / stock.step
          │              │                    │
          │         实体与回读检查        工程图 / 加工准备 / 采样仿真
          └──────────────┴────────────────────┘
                         │
              检查报告、准备等级、版本化交付
                         │
             工程师审阅 → 修改 → 新版本重建和检查
```

### 分层职责

| 层 | 当前实现 | 责任与边界 |
| --- | --- | --- |
| 交互与任务编排 | `workbench.py/.html`、`scripts/demo_chain.py` | 图片/文字新建、对话、任务与版本展示、交付链；是具体应用编排，尚无独立通用 Agent Runtime |
| 工程 Skill | `wheel_skill_contract.py`、`wheel_skill.py`、`text_wheel.py` | 参数约束、来源、已知/未知、重建与等级；图片和文字入口共享部分规则，尚未完全统一 |
| 模型辅助 | `style_agent.py`、`recipe_chat.py`、文字模型提案 | 视觉造型修正、受控对话修改、模板选择；模型提案仍须确定性审核 |
| 几何内核 | `mesh_build.py`、`forged_blank.py`、`machining_step.py` | 构建三类不同范围的几何；几何计算主要在 CPU 上完成 |
| 工程交付 | `drawing.py`、`manufacturing_demo.py` 等 | 工程图、工序与刀具信息、参考 NC、采样材料去除；不构成制造发布 |
| 证据与版本 | `workbench_revision.py`、各阶段 JSON 报告及清单 | 保存参数与来源、修改、失败、产物归属；旧版本的验证不能证明新版本正确 |

### Skill、工作台与 LocalPilot 的关系

`skills/wheel-engineering/` 是可复制的技能包：`SKILL.md` 定义调用和验收契约，`scripts/run.py` 提供启动入口，`references/` 提供安装与评测说明。真实实现和 CAD 依赖在项目运行环境中。工作台直接调用 Python 模块，**不会动态读取 Markdown 来执行建模**。`.agents`、`.claude` 中的入口链接到同一份技能目录。

LocalPilot 是独立项目。本仓库的 `skills/localpilot/` 负责节点前提检查、模型端点交接和基本响应验证；它不是轮毂建模的强制依赖，也没有把整个 LocalPilot Runtime 嵌入当前工作台。未来是否抽出通用 Runtime，应由多个真实 Skill 的共同需求决定。

DGX Spark 是本地模型与应用的部署目标。需要分别记录“Mac 建模 + Spark 模型”和“Spark 全链运行”；模型在 Spark 上响应不等于 CAD 全链已经在 Spark 验收。

## 3. 当前 PRD：V0.1 工程草案工作台

### 用户目标

工程师可以从一张轮毂图或一段文字开始，确认关键规格，生成造型初稿，修改并比较，最后取得与当前配方对应的工程交付草案。

### 输入与约束

- 图片：正面图，可选斜视图；任意多视角融合尚未实现。
- 文字：支持范围内的辐条、凹度、斜面、盲窗等造型需求。
- 工程规格：直径、宽度、PCD、孔数、中心孔、ET；可补充孔型。
- 缺失规格保留为待确认；文字预览可用明确标注的默认值，不让模型编造工程尺寸。
- 工厂 CAD 用于已有照片评测的对照。文字造型库是另一种显式的私有参考输入，不能把模板复用成绩当成新款独立重建成绩。

### 功能需求与当前验收口径

| 功能 | 当前产品行为 | 验收要求 |
| --- | --- | --- |
| 理解与审查 | 提取明确规格，列出默认、未知、被拒绝和被裁剪提案 | 用户尺寸优先；缺项可见；模型越权被拦截 |
| 图片新建 | 从轮廓和规格生成配方、预览，可选视觉 Agent | 保存来源；外观评分与工程尺寸检查分开 |
| 文字新建 | 匹配辐条数的私有轮廓模板；无匹配用简化参数预设 | 模板不携带订单工程尺寸；无效造型提案保留默认；实验预设明确标注 |
| 造型修改 | 白名单参数 → 重建 → 校验 | 工程尺寸走单独确认；新配方不继承旧交付或照片评分 |
| 工程保护 | ET 固定时按中心盘厚度约束调整中心深度；记录调整 | 文字路线下限为 `max(32 mm, 孔座深度 + 锥座高度 + 8 mm)`；不足不能显示全部通过。这是模板构建规则，未证明结构安全 |
| 盲窗与语言语义 | 数量明确时采用原文；一圈默认每辐 3 个并追问；否定优先 | 检查独立刀具组件数量；“凹深”不清零斜面；未变化值不冒充已完成修改 |
| 交付 | 当前版本加工级 STEP、图纸、加工准备与报告 | 检查实体、回读、碎面、尺寸及调整；区分缺失步骤和未通过项 |
| 工作台 | 输入、三维查看、Agent 对话、工程参数确认、版本选择 | 连续新建输入隔离，完成状态正确，新版本自动显示 |
| 本地部署 | 固定 Python 依赖、应用容器、可配置模型端点 | 干净安装与回归；真实模型/真实 CAD/实际部署设备分别留证 |

### 交付物的含义

| 产物 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 配方、来源与调整记录 | 参数可修改并重新生成，过程可复核 | 不代表 FreeCAD/NX 原生可重算特征树 |
| GLB | 造型可预览，执行过所列网格检查 | 不代表 STEP、制造精度或强度验证 |
| 完整造型 STEP 候选 | 仅在实体与回读检查通过后成立；仍需看跳过工序 | 写出文件不代表造型完整 |
| 加工级 STEP | 简化车削回转体、直壁窗口、孔系及毛坯 | 不包含完整辐条造型曲面 |
| SVG/PDF 工程图 | 草案尺寸与技术要求可审阅；PDF 依赖转换环境 | 不保证完整公差、形位要求或工厂批准 |
| 参考 NC 与采样仿真 | 说明加工准备和采样材料去除过程 | 不保证刀柄/夹具/机床碰撞安全，不可据此宣称可直接上机 |

准备等级沿用 [V0.1 定义](product-v0.1.md)：L0 为视觉或未验证草案；L1 需要有效实体和 STEP 回读；L2 还需关键规格及来源齐备并通过检查；L3 是当前几何检查通过且无跳过工序。**L3 不等于完整工程验证，当前不提供 L4/L5。** 所有产物保持 `manufacturing_status=not_released`。

### 已有证据与未完成部分

- **2026-09-28，Spark 照片开发案例**：记录过 5/5 步、57.7 秒的整链运行；这次没有 PDF 和完整造型 STEP。[证据](workbench-hardening.md)
- **13 个已参与标定的尺寸样本**：历史网格 13/13、加工级 STEP 13/13；完整造型 STEP 仅 5/13 通过回读。完整造型旧汇总的部分 L3 标签早于“跳过工序限制”，不能直接当作当前版本等级验收。[历史指标](prd-final-demo.md)
- **2026-09-29，文字修正**：真实 Spark 模型、本机 CAD；有/无盲窗两句通过，第一个加工级 STEP 的实体、回读、碎面与 ET 检查通过。不是本次代码的 Spark 全链结果。[验收数据](evidence/text-hub-fix-20260929.json)
- **主要缺口**：完整造型 B-Rep 的稳定性、未参与调参的新款验证、图片/文字/对话规则的一致性，以及长期任务的恢复与重复稳定性。

## 4. 未来规划：以验收门槛推进

下表是计划，尚未实现的能力不列为当前产品功能。先做深 Wheel Skill，再依据真实需求扩展品类。

| 阶段 | 优先交付 | 进入下一阶段的依据 |
| --- | --- | --- |
| 近期：可靠 Wheel Skill | 统一图片/文字/对话的工程约束与检查；保留失败现场；修 STEP 回读、复杂窗口及孔座；任务恢复与版本一致性 | 冻结配方与资源预算，分别报告 STEP 写出、回读、无缺失造型、尺寸检查、耗时与内存；正常样本无退化，失败样本有可解释修复 |
| V0.2：更可靠的重建输入 | 增加侧/背面观测、工程图与测量证据；改进轮廓和相机拟合；建立未参与调参的测试集 | 独立新款上记录失败率、误差、人工修改量；照片不可观测信息仍保持 UNKNOWN |
| V0.3：工程师修正闭环 | 记录修改前后配方、修改原因、采用/拒绝与验证结果；管理数据授权及训练/评测划分 | 工程师能追溯并撤回修改；在固定测试集上证明规则或模型改进有收益。当前版本记录尚不是自动学习系统 |
| V1.0：第二个领域 Skill | 基于用户需求选择支架、壳体等一个领域；提取确实共用的输入、任务、工具与报告接口 | 第二个 Skill 能复用核心接口并有自己的工程规则和独立验收；这时再判断通用 Runtime 与 LocalPilot 的整合范围 |
| 长期：工程优化与制造协作 | 材料、公差、CAE/FEA、DFM、工厂 CAM 及人工审核衔接；探索减重或成本优化 | 获得仿真、工程师及实际制造反馈后，才讨论相应工程等级与优化效果 |

### 下一轮投入顺序

1. **约束一致性**：将中心盘厚度、孔座余量、来源和等级规则逐步抽成共享检查，避免某条入口通过、另一条入口漏检。
2. **完整造型可靠性**：从正常、回读异常、复杂多面三个代表样本定位，再复测整批；不得通过关闭造型或放宽阈值冒充质量提高。
3. **独立验收与工程师效率**：补新款数据，比较达到相同质量所需的人工时间；单独记录机器等待时间。
4. **交互与恢复**：让调整、失败原因、当前产物范围更易读；完善长任务取消、恢复及失败日志。

近期范围不包括通用 Skill 市场、任意零件自动建模、自动发布制造文件。新功能应先证明对轮毂闭环的可靠性或工程师效率有实际贡献。
