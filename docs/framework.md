# WheelCAM 产品与技术框架 v0.1

日期：2026-09-12。状态：方案草案。

## 1. 产品判断与业务边界

将项目定位为面向轮毂的“图片辅助参数化设计与加工准备工作台”。AI 负责识别造型、提取候选参数、解释修改意图和提出建议；几何内核负责建立实体；CAM 引擎负责计算刀路；后处理器负责生成指定机床的程序。

本期用户已确认加工对象为铸造毛坯，目标为成品轮毂。铸造模具设计、模具加工、熔炼和铸造过程控制作为后续独立方向。

先按单件式、具有周期性轮辐的铸造轮毂建立模板。材料牌号、热处理状态、车型和轮辋规格尚未确定，不能作为生产默认值。

工厂现状未知，架构先支持数字样机和文件交接，再接入工厂工作站。具体 CAD/CAM 产品、许可、API 能力和部署方式在接入前验证。

## 2. 图片输入需要分为三类

| 输入 | 可提供的信息 | 必须补充或确认的信息 |
| --- | --- | --- |
| 同一实物的多视角照片 | 轮辐数量、外观轮廓、可见孔位、局部造型 | 尺度、相机与视角关系、背面结构、关键尺寸；必要时使用扫描或测量 |
| 多张设计效果图 | 设计意图、比例、造型方向 | 各图是否一致、主参考图、隐藏结构、真实尺寸及工程约束 |
| CAD、工程图、扫描及测量资料 | 更可靠的几何或尺寸依据 | 坐标、单位、版本、测量不确定性和文件实际完整性 |

图片中的外观相似度不能作为加工尺寸精度的证明。多张效果图也可能包含相互矛盾的几何，需要标注冲突并由用户选定。

MVP 采用图片轮廓与轮毂模板拟合：识别圆心和周期性结构，提取一根轮辐的造型，调整截面与深度，再通过阵列重建。无图可见的结构采用有出处的模板并明确标注，供工程师确认。

多视图重建作为可选辅助，不是首版的必要前置依赖。COLMAP 官方教程对重建照片提出纹理、重叠与拍摄条件要求；金属反光和重复轮辐因此是需要实测的输入风险。[COLMAP 教程](https://colmap.github.io/tutorial)

## 3. 成品设计和现有毛坯必须共同建模

系统至少保存三个独立对象：目标成品、实际毛坯、加工装配。加工装配包含毛坯、夹具、定位与坐标变换。

已有毛坯时，造型自由度受其材料分布限制。普通切削只能去除材料，目标成品超出毛坯的区域不能通过调整刀路得到。轮辐主造型若已由铸造形成，后续加工也不能任意改成另一种轮辐结构。

没有实际毛坯数据时，可以建立明确标记为“假设”的毛坯用于展示；匹配结果属于概念分析，不能据此认定真实零件可加工。

匹配检查包括：

- 将成品和毛坯对齐到已确认的基准，统一单位与坐标。
- 检查成品在毛坯之外的缺料区域，以及关键表面的局部加工余量。
- 结合毛坯公差或扫描误差，检查余量是否足够且不会导致局部过薄。
- 区分保留的铸造表面与需要加工的表面，明确夹持和刀具可达性。
- 对不匹配情况提供修改设计、选择其他毛坯或回到铸造设计的处理路径。

几何包含关系只是必要条件，仍需结合夹持、刚性、刀具可达性和工艺要求判断。材料内部缺陷与真实材料性能另依检测和制造记录判断。

RONAL 的公开生产流程包含铸造后的去毛刺、测量与 X 射线检查。本项目据此将毛坯几何与质量记录分开管理，避免由几何模型推断材料内部质量。[RONAL 生产流程](https://www.ronalgroup.com/en/production/)

## 4. 产品模块

| 模块 | 核心功能 | 输出 |
| --- | --- | --- |
| 项目与资料 | 管理图片、主参考图、工程图、CAD、扫描和来源 | 带版本的设计输入 |
| 图片理解 | 识别造型、视角、轮辐数量与重复关系，显示不确定项 | 候选特征与图片标记 |
| 参数编辑 | 录入规格、尺寸、轮辐曲线和工程约束，关联来源 | 经确认的轮毂规格 |
| CAD 生成与检查 | 模板重建、实体检查、参数修改、剖面和版本对照 | 工程实体、预览与几何报告 |
| 毛坯匹配 | 导入与对齐、余量分析、缺料及保留表面检查 | 匹配报告 |
| 工艺规划 | 识别加工面与孔系、组织装夹、选择机床及刀具 | 工序与装夹方案 |
| CAM 与程序 | 生成刀路、材料去除仿真、机床后处理、程序复核 | CAM 工程、NC 草稿和验证记录 |
| 工程交付 | 汇集审核状态、图纸、刀具单、装夹单与文件版本 | 可追溯的交付包 |

建议主界面由图片与资料区、三维视图区、参数区组成；另设毛坯检查、工艺准备和交付页面。每个参数旁可查看其来源和是否已确认。

## 5. 轮毂参数与建模方法

### 5.1 必需的工程信息

| 信息组 | 示例字段 |
| --- | --- |
| 尺寸与轮辋 | 公称直径、宽度、轮辋截面规格、偏距 ET、中心孔 |
| 安装与接口 | 孔数、节圆直径 PCD、孔径、紧固件座面、安装面、制动器避让空间 |
| 轮辐造型 | 轮辐数量、曲线、截面、厚度、凹深、圆角及背部结构 |
| 技术要求 | 基准体系、尺寸与几何公差、粗糙度、跳动要求 |
| 材料与使用 | 材料牌号、热处理状态、载荷目标、应用和适用验证要求 |
| 毛坯 | 毛坯实体、版本、工艺状态、偏差范围、加工余量与定位基准 |

公称轮辋直径不等于照片里测得的最外缘直径。轮辋截面等功能几何应使用经确认的工程规格，不能从效果图随意推断。

概念建模可以使用显式假设值；进入加工准备时，相关尺寸、公差、毛坯和材料字段必须完整。缺失值保留为未知，不能由 AI 静默填成制造参数。

### 5.2 CAD 路线

建议优先验证 Python + CadQuery + Open CASCADE：旋转生成轮辋和中心部分，以草图、拉伸、放样等建立轮辐，通过圆周阵列、布尔运算和圆角构造成品实体。CadQuery 官方文档说明其基于 Open CASCADE 的 Python 绑定，支持参数化建模和 STEP 输出。[CadQuery 简介](https://cadquery.readthedocs.io/en/latest/intro.html)

首版从一类简单轮辐模板起步。复杂扭曲轮辐、连续自由曲面和易失败圆角先做几何可行性试验；必要时使用外部 CAD 设计的模板或通过适配器继续精修。此方案不承诺任意图片都能自动转成完整工程实体。

保存参数 JSON、模板版本和建模配方作为可编辑源；STEP 用于交换几何，GLB 用于浏览器预览。CadQuery 的导出格式不自动携带其完整参数化构建历史，因此不能把 STEP 当作原生特征树的替代品。[CadQuery 导入导出说明](https://cadquery.readthedocs.io/en/latest/importexport.html)

工程图还需独立的标注流程：几何投影与尺寸、公差、基准和技术要求分别管理，不能把未标注的投影视图标为正式加工图。

### 5.3 AI 与确定性执行的分工

模型输出受约束的结构化参数、模板编号和候选修改；后端验证后调用已知的几何操作。首版不执行模型随意生成的 Python 脚本。

每个关键字段保留来源类别：图片估计、图纸标注、测量输入、模板继承、人工输入或派生计算。保存原始依据及审核状态。置信度用于提示补充资料，不替代尺寸验收。

几何任务独立运行，设置资源限制、超时和错误产物保留。首版即使模型输出无效，也应能回到参数编辑，保留上一版有效 CAD。

## 6. 加工与数控输出

### 6.1 工艺对象

典型候选工序包括端面、内外回转表面、中心孔等车削，以及安装孔、气门孔和经设计允许的局部铣削。实际内容、顺序、工序间毛坯和装夹次数由轮毂结构、毛坯状态及工厂设备确定。

每个装夹分别记录工件坐标、定位基准、夹具、夹持区域、刀具及刀柄、可达范围和工序顺序。多次装夹需要继承前序加工后的毛坯状态；多台机床分别生成程序与装夹说明。

已有铸造轮辐通常只需要规定区域的后续加工。不能将效果图里全部表面都自动列为铣削区域。

### 6.2 CAM 策略

首期自研范围为设计参数、几何模板、毛坯分析、工艺特征和任务编排；刀路算法和后处理优先使用成熟 CAM。

先定义 CAM 适配接口，支持文件交换和人工交接。待确认工厂软件后，再接其自动化 API。Fusion 可作为候选：其官方 CAM API 提供加工操作和刀路相关自动化能力，NCProgram API 支持生成机器专用 NC 代码。[Fusion CAM API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/CAMIntroduction_UM.htm) · [NCProgram 后处理 API](https://help.autodesk.com/cloudhelp/ENU/Fusion-360-API/files/NCProgram_postProcess.htm)

接口存在不代表可以作为任意服务器上的无界面 CAM 服务。是否通过桌面插件、受许可的工厂工作站或其他方式运行，在技术验证时确认。NX、Mastercam 等仅为随工厂环境评估的备选，当前不承诺具体自动化能力。

### 6.3 代码的生成与验证

程序流程为：批准的工序与装夹 → CAM 刀路 → 刀路及材料去除检查 → 指定机床后处理 → NC 草稿 → 程序与机床验证 → 工艺确认 → 受控试切。

需要绑定的不只是“FANUC”或“西门子”品牌，还包括具体机床型号、轴配置、控制器版本、机床专用功能、刀具夹具和后处理器版本。Autodesk 文档同样将机床配置、后处理设置和操作选择列为 NC 输出的组成部分。[NC Program 配置](https://help.autodesk.com/view/fusion360/ENU/?contextId=MFG-REF-NC-PROGRAM)

验证区分以下层次：

1. 几何与工艺检查：余量、加工区域、刀具可达性、夹持及工序依赖。
2. CAM 检查：材料去除、过切、残料，以及刀具和刀柄与工件、夹具的干涉。
3. 机床与程序检查：行程、运动学、换刀及退刀动作、偏置、后处理输出和控制器语义。
4. 现场确认：对刀与装夹核对、受控空运行或试切、首件测量和工艺调整。

应核实所选仿真究竟验证的是 CAM 刀路、后处理运动还是最终 NC 文本及控制器行为，记录覆盖范围。工具路径动画不能被显示为“最终程序已验证”。

当前无机床与后处理配置，可以完成数字展示与适配器设计；NC 输出不得标记为已适配真实机床。首个加工验证选择一道工序、一套装夹和一台实际机床，再扩展多工序车铣。

## 7. 软件架构

建议采用模块化单体 API，配合独立的几何任务进程和工厂 CAM 工作站适配器。初期无需将每个模块拆成微服务。

```text
浏览器工作台：项目 / 图片 / 参数 / 3D / 毛坯检查 / 工艺 / 交付
                               │
                     API 与任务编排服务
                  ┌────────────┼────────────┐
               图片理解      版本与审核      工艺规划
                  │              │              │
            结构化候选参数     元数据存储      CAM 适配层
                  │              │              │
           几何生成与检查 ─── 文件存储 ─── 工厂 CAM 工作站
                                                │
                                       刀路 / 后处理 / 验证
```

| 层 | 建议 | 选择理由与验证边界 |
| --- | --- | --- |
| 工作台 | React + TypeScript + Three.js | 资料、参数和三维展示；浏览器网格不作为工程几何真值 |
| API | Python + FastAPI | 连接参数、任务和几何服务；具体依赖版本在实现时锁定 |
| 几何 | CadQuery + OCP / Open CASCADE | 可程序化建立实体；先验证目标轮辐与圆角的稳定性 |
| AI | 可替换的视觉语言模型适配层 | 只输出结构化候选，不锁定供应商；用真实样本评测 |
| 元数据 | 单机 MVP 可用 SQLite，协作阶段使用 PostgreSQL | 管理项目、参数、版本、任务和审核 |
| 文件 | MVP 本地目录，后续接对象存储 | 保存原图、CAD、CAM、报告和交付文件 |
| 异步任务 | MVP 数据库持久化任务 + 独立 worker | 长时间几何任务可取消、重试和恢复；扩容时再引入队列 |
| CAM | 文件适配起步，再接具体软件 API / 桌面插件 | 适应工厂已有环境与许可，不把桌面依赖藏在 Web 服务内 |

这是建议结构，相关服务目录尚未创建。

```text
wheel-cam/
  apps/web/                  工作台
  services/api/              项目、参数、任务与版本
  services/geometry/         模板、实体生成、毛坯分析
  services/vision/           图片候选特征提取
  integrations/cam/          CAM 文件及自动化适配器
  packages/contracts/       数据契约
  assets/templates/         有出处、经验证的轮毂模板
  fixtures/reference-cases/ 几何与加工基准样例
  docs/                      框架和工艺接入记录
```

## 8. 版本、恢复和验证状态

建议核心对象包括 Project、InputAsset、WheelSpec、CADRevision、BlankRevision、GeometryCheck、Setup、Operation、MachineProfile、PostProfile、CAMJob、VerificationRun、ReviewRecord 和 ReleaseBundle。

所有下游结果绑定输入版本与文件摘要。成品、毛坯、坐标、工序、刀具夹具、机床或后处理器变化后，依赖它们的结果需标为过期并重新计算。历史结果保留，不覆盖成新版本的验证证据。

几何任务先写临时产物，成功后登记有效版本；失败保存错误记录，不覆盖上一版。支持幂等重试与任务取消。

状态分别描述建模、工艺程序和产品验证：

- 建模：概念草案 → 几何已检查 → 工程设计已审核。
- 工艺程序：资料待补 → 工艺已确认 → 刀路已检查 → NC 草稿 → 程序验证已完成 → 试切已确认。
- 产品验证：按选定用途及要求单独管理，不能由“试切已确认”自动推得。

轮毂产品验证需结合尺寸、跳动、材料状态和缺陷检查，以及适用的疲劳、冲击等设计验证与实物试验。具体标准及验收参数由用途、销售市场和工程团队确定。厂商公开质量流程可供参考，本框架未确定适用标准或数值。[RONAL 质量流程](https://www.ronalgroup.com/en/quality/)

## 9. 主要技术风险与处理方向

| 风险 | 框架中的处理 |
| --- | --- |
| 图片缺少尺寸和背面信息 | 显示未知项和假设，要求工程尺寸补充 |
| 图像生成模型只产生外观网格 | 参数化模板重建工程实体，预览网格单独保存 |
| 复杂轮辐布尔或圆角失败 | 先做几何样例验证，提供修改参数及 CAD 精修入口 |
| 现有毛坯不支持目标设计 | 建模阶段进行余量与缺料检查 |
| 更改模型后 CAM 选面失效 | 用加工特征标识及几何校验重新匹配，失败时要求重选 |
| 机床、刀具、夹具未知 | 首版完成数字样机，接入后再验证 NC |
| CAM API 或许可不适合部署方式 | 接入前验证，保留文件交接路径 |
| 仿真范围不足或证据过期 | 记录覆盖范围，按输入版本失效和重算 |

## 10. 后续扩展

在铸后加工流程验证后，可增加更多轮毂模板、复杂曲面、多机床、多装夹与五轴加工，以及工艺模板复用和首件测量反馈。

铸造扩展应另立分支：成品设计 → 铸件与余量设计 → 模具与分型设计 → 铸造工艺仿真及确认 → 模具 CAM。收缩补偿、浇注与冷却等需要材料及工艺依据，不能通过成品模型简单等比例缩放完成。
